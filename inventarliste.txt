1.1 Kern-Tools (direkt verfügbar)

Tool: terminal
  Zweck: Shell-Befehle ausführen
  Eingaben: command, workdir, timeout, background, pty
  Ausgaben: stdout/stderr, exit_code, cwd
  Typische Verwendung: Builds, Git, Python-Skripte, Systemprüfungen

Tool: read_file
  Zweck: Datei lesen (mit Paginierung)
  Eingaben: path, offset, limit
  Ausgaben: Inhalt mit Zeilennummern, total_lines
  Typische Verwendung: Code lesen, Configs prüfen, JSON/YAML einsehen

Tool: write_file
  Zweck: Datei erstellen/überschreiben
  Eingaben: path, content
  Ausgaben: Erfolg, verified
  Typische Verwendung: Scripts schreiben, Configs anlegen

Tool: patch
  Zweck: Find-and-replace in Dateien
  Eingaben: path, old_string, new_string
  Ausgaben: unified diff
  Typische Verwendung: Code-Edits, Config-Änderungen

Tool: search_files
  Zweck: Inhalte oder Dateinamen suchen
  Eingaben: pattern, target, path, limit
  Ausgaben: matches mit Zeilennummern/Pfaden
  Typische Verwendung: Code-Navigation, Symbol-Updates finden

Tool: execute_code
  Zweck: Python mit Hermes-Tools programmatisch
  Eingaben: code, reset
  Ausgaben: print-output, gespeicherte Dateien
  Typische Verwendung: Batch-Operationen, API-Calls mit Logik, Filtern

Tool: vision_analyze

Tool: web_search

5. AUTOMATISIERTE GESCHÄFTSABLÄUFE (WORKFLOWS)
================================================================================

Workflow 5.1: Werbemaschine (werbemaschine.sh) — alle 5 Stunden
  1. State laden (campaign_state.json — Historie, Pointer, CTA-Variante)
  2. Nische nach weights.json + highlight-Flag auswählen (×1.8 Gewicht)
  3. Produkt aus products.json ziehen (Rotation ohne Duplikate)
  4. Pin bauen: make_pin() → 1000×1000, Produktbild, Preis-Banner, CTA-Pill
  5. Zernio: POST /v1/media/upload-direct → öffentliche URL
  6. Zernio: POST /v1/posts (nur Pinterest, boardId der Nische, publishNow=true)
  7. Status-Check: GET /v1/posts/{id} → status='published'?
  8. State speichern (Zeitstempel, Slug, ASIN, Post-ID, CTA-Variante)
  9. Bei Fehler: Telegram-Alert

Workflow 5.2: Social Daily (social_daily.py + social_daily.sh) — täglich 17:00 UTC
  1. Zernio: Zwei Posts (Pinterest + Instagram) für Zernio-Kampagne
  2. BulkPublish: Threads-Post (@gamerbrosis14)
  3. BulkPublish: TikTok-Video (@gamerbrosis14)
  4. BulkPublish: YouTube-Video (Gamerbrosis) — Rotation
  5. Status-Check über jede Plattform
  6. Bei Fehler: Telegram-Alert (aktuell: Threads/TikTok-Kanal nicht konfiguriert für DS24)

Workflow 5.3: Preisradar (radar.sh) — täglich 04:30 UTC
  1. Amazon-Preise für alle ASINs in products.json scrapen
  2. Vergleich mit radar.json (letzte Preise)
  3. Preisstürze erkennen (-15% oder mehr)
  4. Alert-Log schreiben
  5. Deal-Gifs (animierte Pins) für Preisstürze vorbereiten
  6. Bei Alarm: Telegram-Alert

Workflow 5.4: DIY-Pin-Engine (diy_engine.py) — als Teil der Werbemaschine
  1. diy_guides.json laden (nur verifizierte Kits: ≥4.4★, ≥300 Bewertungen, 30-80 €)
  2. Kit-Amazon-Seite scrapen (Desktop-UA, /dp/<ASIN>)
  3. HiRes-Galerie extrahieren (ppd-Zone, SL1000)
  4. Kontaktbögen bauen → vision_analyze: HANDS vs. POSE vs. RENDER
  5. WERKELN-Filter: nur echte Arbeitsfotos behalten
  6. Duplikat-Filter (Perceptual-Hash, Hamming ≤24)
  7. Größenfilter (min-Kante <400px → raus)
  8. make_diy_pin7.py: v6-Layout + Produktstreifen
  9. Zernio: Upload + Post (nur Pinterest, 08:17 UTC next morning)
  10. Status-Check → State speichern

Workflow 5.5: 22h-Report (daily_report.sh) — täglich 22:00 UTC
  1. Alle Plattform-Metriken sammeln:
     - Pinterest: Zernio analytics/daily-metrics + PartnerNet-Screenshot (vision_analyze)
     - GA4: Klicks, Sessions, Conversions
     - Threads: 658 Posts
     - TikTok: 657 Videos (@gamerbrosis14)
     - YouTube: 679 Videos (Gamerbrosis)
  2. KPI-Berechnung: Klicks, CVR, EPC, Einnahmen
  3. Tagesbericht formatieren (copy-paste-freundlich)
  4. An Andreas liefern (deliver='origin')

Workflow 5.6: Blog-Artikel-Automat (github-pages-blog-automation) — alle 3 Tage
  1. Thema aus seasonal.yaml + Kalender-Logik wählen
  2. Artikel generieren (SEO-optimiert, DACH)
  3. Produkte aus products.json einbetten
  4. Auf GitHub Pages deployen
  5. Telegram-Benachrichtigung

Workflow 5.7: Preisradar-Deal-Gifs (dealgifs.sh) — täglich 06:15 UTC
  1. radar.json nach Preisstürzen durchsuchen
  2. Animierte GIFs für Pinterest-Pins bauen
  3. Zernio: Upload + Post (Pinterest-only)

Workflow 5.8: TikTok-Assets (tiktok_assets.sh) — täglich 03:00 UTC
  1. Amazon-Bilder reparieren (repair_images.py — inkrementell)
  2. TikTok-9:16-Video-Assets aus Bildern generieren
  3. Für social_daily.py vorbereiten

7. RISIKEN UND ABHÄNGIGKEITEN

7.1 Ohne menschliche Freigabe laufende Schritte

Pinterest-Pins (Werbemaschine)
  Automatisierung: Vollautomatisch
  Risiko: Falscher Preis/Titel wenn Amazon-ASIN recycelt wird
  Gegenmaßnahme: VERTRAUENSREGEL — Live-Prüfung vor Post

CTA-Rotation (campaign_engine.py)
  Automatisierung: Vollautomatisch
  Risiko: Niedrige Conversion bei falscher CTA-Variante

Preisradar (radar.sh)
  Automatisierung: Vollautomatisch, Alert nur bei Sturz
  Risiko: False-Positives durch Amazon-Preisschwankungen

22h-Report (daily_report.sh)
  Automatisierung: Vollautomatisch
  Risiko: Metriken ohne Kontext können irreführen

Blog-Artikel (github-pages-blog-automation)
  Automatisierung: Vollautomatisch
  Risiko: Qualität hängt von Prompt und Produktdaten ab

Social Daily (Threads/TikTok/YouTube)
  Automatisierung: Vollautomatisch
  Risiko: Kanal-Konfiguration (aktuell: DS24-Kanäle fehlen)

DIY-Pins (diy_engine.py)
  Automatisierung: Vollautomatisch
  Risiko: Foto-Qualität hängt von Amazon-Galerie ab

Placement-Daily (placement_daily.sh)
  Automatisierung: Vollautomatisch
  Risiko: Veraltete Platzierungen wenn Struktur sich ändert

7.2 Single-Point-of-Failure-Abhängigkeiten

Zernio API
  Auswirkung: Pinterest + Instagram-Pins komplett lahm
  Workaround: Manuelle Posts via Browser

Amazon ASINs
  Auswirkung: Produktdaten falsch/recycelt
  Workaround: Live-Prüfung via /dp/<ASIN>

OpenRouter
  Auswirkung: LLM-Cronjobs (Blog, Report, saison-Kalender) pausiert
  Workaround: Ollama als Fallback (qwen2.5-coder:3b)

Telegram
  Auswirkung: Keine Alerts bei Problemen
  Workaround: deliver='origin' als Fallback

GitHub Pages
  Auswirkung: Site nicht erreichbar
  Workaround: Lokales Backup in andreasstehmann-links_backup_*

Pillow (Python)
  Auswirkung: Pin-Rendering unmöglich
  Workaround: System-Python hat Pillow nicht — venv erforderlich
